# Split `RStatement` into `RExpressionStatement` and `REmptyStatement`

Status: done. Aether landed in #48. Air's half is uncommitted on `feature/statements`, on top of the snapshot commit `1964a3de`. See [Outcome in air](#outcome-in-air) for where it differs from this plan.

Aether's `RStatement` has two optional slots, `expression: AnyRExpression?` and `semicolon: ';'?`. This plan splits it into two node kinds behind a union, the way Biome's JavaScript grammar does. When you hold an `RExpressionStatement`, its expression slot is always filled.

The change lands in aether first. Air picks it up afterwards by copying the grammar and re-running codegen on `feature/statements`, before that branch merges.

## The new grammar

```diff
-RStatementList = RStatement*
+RStatementList = AnyRStatement*

-// A single statement
-//
-// Both slots are optional, using the same trick as `RArgument`:
-// - `1`  -> expression, no semicolon
-// - `1;` -> expression + semicolon
-// - `;`  -> no expression, semicolon only, since R allows `;;` and a leading `;`
-//
-// A statement with neither slot filled is never generated by a parse without
-// syntax errors.
-RStatement =
-	expression: AnyRExpression?
-	semicolon: ';'?
+AnyRStatement =
+	RExpressionStatement
+	| REmptyStatement
+
+// `1` or `1;`
+RExpressionStatement =
+	expression: AnyRExpression
+	semicolon: ';'?
+
+// A `;` with no expression before it, like each `;` in `{;;}`
+REmptyStatement =
+	';'
```

Here is how inputs map to nodes:

| input    | statements                                                         |
| ---      | ---                                                                |
| `1`      | `RExpressionStatement { 1, missing }`                              |
| `1;`     | `RExpressionStatement { 1, ; }`                                    |
| `{;}`    | `REmptyStatement { ; }`                                            |
| `{1;;2}` | `RExpressionStatement { 1, ; }`, `REmptyStatement { ; }`, `RExpressionStatement { 2, missing }` |
| `{1\n;}` | `RExpressionStatement { 1, missing }`, `REmptyStatement { ; }`     |

Syntax kinds: `R_STATEMENT` is replaced in place by `R_EXPRESSION_STATEMENT` and `R_EMPTY_STATEMENT`. The kinds after it get new numbers. That doesn't matter: nothing is published, both repos regenerate, and no snapshot prints kind numbers.

## What Biome JS does

Taken from `~/files/programming/biome` at `afe43a88`.

### Grammar (`xtask/codegen/js.ungram`)

```
JsStatementList = AnyJsStatement*

AnyJsStatement =
    JsBlockStatement
    | JsEmptyStatement
    | JsExpressionStatement
    | ...

JsEmptyStatement =
    ';'

JsExpressionStatement =
    expression: AnyJsExpression ';'?
```

`expression` is required. `1;;` is a `JsExpressionStatement { 1, ; }` followed by a `JsEmptyStatement { ; }`. The parser creates an empty statement when a statement starts with `;` (`parse_empty_statement()` in `biome_js_parser/src/syntax/stmt.rs`).

### Statement list formatter (`js/lists/statement_list.rs`)

Empty statements are joined without a line break:

```rust
for statement in node.iter() {
    match statement {
        AnyJsStatement::JsEmptyStatement(empty) => {
            join.entry_no_separator(&empty.format());
        }
        _ => {
            join.entry(statement.syntax(), &format_or_verbatim(statement.format()));
        }
    }
}
```

### Empty statement formatter (`js/statements/empty_statement.rs`)

- It calls `format_removed()` on the `;`. The one exception is an empty statement used as a loop or `if` body, like `for (;;);`, where the `;` is kept.

- It writes its own leading comments inside `fmt_fields()`, with a hard line break first when one of the comments is a line comment or sits on its own line.

### Expression statement formatter (`js/statements/expression_statement.rs`)

It writes `expression.format()` with no check for a missing expression, followed by `FormatStatementSemicolon`, which follows the `semicolons` option.

### Comment placement (`comments.rs`)

Block bodies and function bodies skip empty statements:

```rust
let first_non_empty = block_statement
    .statements()
    .iter()
    .find(|statement| !matches!(statement, AnyJsStatement::JsEmptyStatement(_)));

match first_non_empty {
    None => CommentPlacement::dangling(block_statement.into_syntax(), comment),
    Some(statement) => CommentPlacement::leading(statement.into_syntax(), comment),
}
```

Another rule never attaches a comment to an empty statement. If the comment would lead an empty statement, it trails the preceding node instead.

### Where R differs from JS

- **Empty statements only appear in statement lists.** `if (TRUE) ;` and `while (x) ;` are syntax errors in R, so there is no loop-body case.

- **No `RBogusStatement` is needed.** `JsStatementList` holds `JsBogusStatement`. Aether's `parse_statement_list()` always wraps what it parses in a statement, and puts unparseable input into the expression slot as an `RBogusExpression`. So `AnyRStatement` needs no bogus variant, and the restricted-union collapse described in `docs/deviations.md` can't happen.

- **The `;` is always removed.** Air has no semicolon option.

## Benefits

### Grammar

- **No invalid state.** Today the grammar can express `RStatement { missing, missing }`, and a comment has to explain that it never happens. After the split, that state can't be written down.

- **Never missing in practice.** In aether, `RExpressionStatement.expression` is never missing, even in trees with errors. The non-`;` branch of `parse_statement_list()` always produces either an expression or an `RBogusExpression` with at least one token. Consumers still get a `SyntaxResult`, but it is never `Err` for aether-produced trees.

- **Each node says what it is.** An empty statement is its own kind, not an expression statement with a hole. `deviations.md`, the corpus snapshots and the LSP syntax tree view all read better.

### Formatter (air)

- **`FormatRStatement` splits into two simple rules.** `FormatRExpressionStatement` writes the expression, then calls `format_removed()` on the `;`. `FormatREmptyStatement` only calls `format_removed()`. Neither has a branch for a missing expression.

- **Skipping empty statements in the list is one `match` arm.** The swap item "expression-less statements emit nothing and don't produce blank lines" becomes Biome's `entry_no_separator()` arm. Air's `JoinNodesBuilderExt` already has `entry_no_separator()` (`joiner_ext.rs:85`).

- **`position()` gets a typed result.** The swap item `{ if (a) 1;; }` becomes "the last `RExpressionStatement` in the list", and the result is guaranteed to have an expression.

- **Comment placement copies Biome directly.** "Lead the first non-empty statement, otherwise dangle" and "never attach to an empty statement" become `matches!` and `can_cast()` checks. These are rules Biome has already tested, not new ones written in terms of `expression().is_none()`.

- **Curly-curly gets tighter types.** `RCurlyCurly.statement_inner` becomes an `RExpressionStatement`. An inner `{;}` is now a different node kind, not a statement with a missing expression that `as_curly_curly()` has to reject.

- **Directives have one target.** `directive_node()` maps `R_EXPRESSION_STATEMENT` parents to the statement. An empty statement has no expression for a `# fmt: skip` or `# fmt: table` to apply to.

### Downstream tooling

- **Walks get simpler.** Linter rules, symbol walks and range formatting can use `find_map(AnyRStatement::as_r_expression_statement)` and work with expressions directly, instead of `filter_map(|s| s.expression())` with a "why is this `None`?" question each time.

## Tradeoffs

- **Every list walk matches on a union.** Reaching an expression from a list item takes two steps: `as_r_expression_statement()`, then `expression()`, which returns a `SyntaxResult`. With the merged node it was one `Option`. Don't add a helper for now. Add one to `aether_r_syntax` (in the style of `argument_ext.rs`) if a third call site wants it.

- **The required slot still returns a `SyntaxResult`.** The error path doesn't go away for consumers. What changes is that a missing expression now means a broken tree, handled the same way as every other required field, instead of the normal representation of `;`.

- **It no longer matches `RArgument`.** `RArgument { name?, value? }` keeps its merged optional slots for `f(,,)`. That's fine: an argument hole is a different concept, and Biome models array holes separately too (`JsArrayHole`).

- **More generated surface.** One union, two nodes and two formatter rules instead of one node and one rule.

- **Churn in both repos.** Every aether corpus snapshot that contains a statement changes, as do air's 39 parser snapshots and 2 LSP snapshots. All of it is mechanical, and the checks below prove it.

## Alternatives rejected

- **Keep the merged `RStatement`.** It has an unrepresentable-in-practice state, and every consumer handles `None` as a normal case. That's the reason for this plan.

- **Keep `RExpressionList` and put `;` siblings in it.** The `;` is no longer tied to its expression, `# fmt: skip` would skip the expression but not its `;`, and `1; # c` makes the comment trail the `;` node. There is also no statement node for the LSP or for lints to work with.

- **Make `;` a variant of `AnyRExpression`.** Then `1 + ;` and `if (;) x` are well typed, and every match on an expression needs an arm for something that isn't one. R's `gram.y` treats `;` as a separator, never an `expr`.

#### Comment placement treats empty statements as invisible

One rule in `comments.rs`, which covers both of Biome's rules and the cases Biome leaves to its defaults:

- When a comment's preceding or following node is an `REmptyStatement`, replace it with the nearest sibling `RExpressionStatement` in that direction, or with nothing if there isn't one.

- Then place the comment the usual way: an end-of-line comment trails the preceding statement, otherwise it leads the following statement, otherwise it dangles on the enclosing `RBracedStatements`.

| input              | comment placement                      | output                  |
| ---                | ---                                    | ---                     |
| `{\n  1 # c\n  ;\n}` | trails `1`                           | `{\n  1 # c\n}`         |
| `{\n  1\n  ; # c\n}` | trails `1`                           | `{\n  1 # c\n}`         |
| `{\n  ; # c\n  1\n}` | leads `1`                            | `{\n  # c\n  1\n}`      |
| `{;# c\n}`         | dangles on the braces                  | `{\n  # c\n}`           |

Write the expected outputs in the tests from what the formatter actually does once the rule exists. The table shows the intent, not byte-exact output.

`place_leading_or_dangling_body_comment()` gets the same treatment: lead the first `RExpressionStatement` of the body, and dangle on the braces if there isn't one.

Where the rule hooks in: find the right spot in the `CommentStyle::place_comment()` chain in `comments.rs`, before the rules that look at statements. Biome's version is in `biome_js_formatter/src/comments.rs`, around lines 827, 912 and 1016 at `afe43a88`.

## Decisions

- A top-level `;` stays an `REmptyStatement` plus an error diagnostic. It is not wrapped in a bogus node, so the node shape doesn't depend on scope.

- All empty-statement and semicolon formatting lands in air now, tested with hand-built trees marked `TODO(aether)`. The swap replaces them with snapshot specs.

- `{;}` and `{;;}` format as `{}`.

- Comment placement treats `REmptyStatement` as invisible, falling back to the nearest `RExpressionStatement` on each side.

- A blank line before a lone `;` is kept, as Biome does.

- No helper for reaching an expression from an `AnyRStatement` yet.

- `# fmt: skip` keeps `x;` verbatim, `;` included.

- A `;` doesn't disqualify curly-curly. It is removed like any other `;`.

## Outcome in air

Where the implementation differs from the plan above:

- `# fmt: skip` didn't actually suppress the statement in P6. `directive_node()` had no arm for a node whose parent is the statement list, so only the expression was suppressed and the `;` was still removed. `directive_node()` now maps `R_STATEMENT_LIST` children to themselves. No formatter snapshot moved.

- Curly-curly accepts a `;`. Rejecting it wasn't idempotent: `fn({{ x }; })` formatted as nested braces with no `;` left, which is curly-curly on the next pass.

- `RBracedStatements` formats `statements` in the `Empty` and `EmptyWithDanglingComments` variants too, so the removed `;` tokens in `{;}` are still visited.

- `entry_no_separator()` takes the node. Its lines before carry over to the next `entry()`, and it doesn't count as an element, so `{;\n\n1}` gets no leading blank line.

- The comment table's dangling case is `{;# c\n}`. In `{;# c}` the comment swallows the `}`.

- The hand-built tests skip the reparse check when the output keeps a `;`, since tree-sitter hides it. Only the `# fmt: skip` case does.

- Not tested: a comment after the outer `;` of curly-curly, like `fn({{ x }; # c\n})`. Its output is unstable, but `fn({{ x } # c\n})` already is on `main`, so that's a separate curly-curly bug.
